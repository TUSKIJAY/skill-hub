# 表达与状态

先回答：这次变了什么；现在能做什么；怎么确认；还差什么；下一步谁做什么。首次或久别补一句项目用途。用具体的打开、输入、看到、保存等动作，不用术语堆砌或生活比喻替代证据。

状态固定词表（图例是词表，不是任务清单）：
- verified / 已验证：记录在指定时间、场景和范围内通过。历史通过不等于当前在线、本地通过不等于部署完成。
- in_progress / 进行中：有明确的正在执行记录，尚未达到条件。计划中不算进行中。
- blocked / 受阻：明确条件阻止继续；写障碍、谁解除、解除后做什么。
- unverified / 未验证：没有充分通过记录；可能已做部分，不等于未开始或不支持。

通过条件来自项目已有目标；新建议显式标明“建议”，不替用户扩大范围。遇到同范围相反证据，不继续用旧通过记录覆盖新失败。失败、暂停、已实现未测试用事实说明，不新增颜色。整个项目完成必须满足项目约定，不能按本页选取项数推断。

页面保持已认可的样式：一句结论、必要背景、能力列表、下一步；详情用原生折叠，记录藏在对应结论附近。小面积状态色总配文字和符号；少量留白与分隔，不增加大块图例说明框、装饰箭头、虚假百分比或数字看板。默认无连线；只有确有依赖且有助理解时另画图。

当前需要用户做的事与未来测试前置条件分开；历史阻碍不自动变成现在要求用户解锁或操作设备。报告本身不产生新的权限要求。保留重要限制在摘要，细节中写时间、条件、实际观察、边界及证据入口。
